## Decisions made in this plan

The design is approved, so these only fix what it left to implementation or where the original brief and the design differ. Where the brief and the approved design conflict, the design wins and the report says so.

- **P1. Slice 1 is split backend first.** FEAT-001 creates the shared fixture `xamops-service/src/test/resources/k8s/k8s-reason-codes.json` that the frontend contract test in FEAT-002 reads, and the server gates exist before any UI offers a control.
- **P2. The slice 1 shell hosts today's tabs unchanged.** Each lazy section renders the existing tab component for its subtab (for example Nodes › Utilization renders `EksPerformanceTab`). That keeps every tab's data reachable if the run stops after slice 1. Slice 2 replaces them with the restyled panels.
- **P3. The section registry grows by slice; there are no placeholder panels.** `EKS_SECTIONS` lists only subtabs that render real content. Slice 1 registers the 11 legacy targets plus `automation/overview`; later items add `overview/events`, the cost subtabs, `nodes/node-groups`, `security/compliance`, `security/runtime`, `data-sources/*` and the other five Automation subtabs. An unregistered `sub` falls back to the section default (§5.1), so links never break.
- **P4. Automation is rebuilt, not uncommented.** The brief's "uncomment `EksAutoscalingTab` wiring" is superseded by design D11: that tab fakes success (E2) and carries misleading copy. "Re-enabled" means the Automation primary section is wired into the page (FEAT-002) and completed in FEAT-005. The old tab and `useEksAutoscaling.ts` are deleted in FEAT-004.
- **P5. Legacy `resources` maps to `workloads/resources`**, not the brief's `nodes/utilization` (design §4.3: that tab renders HPAs, PVCs, Services, Ingresses, Jobs and Events).
- **P6. Other brief items the design settled.** Container Insights is labelled "Configured · data freshness not checked" with no new AWS call (D3); no version-support badge (D15); access is one chip, not a per-row column (§4.1, F8); recommendations come from the vertical engine, and the snapshot endpoint is no longer read (D8); `CloudK8sHelpModal.tsx` is deleted (D11).
- **P7. Demo routes land with the first caller.** Capabilities in FEAT-002; vertical endpoint 1 in FEAT-003; every `/api/eks/autoscaling/**` GET, every mutation shape (403 `K8S_DEMO`) and vertical endpoint 4 in FEAT-005. Nothing calls an engine or autoscaling path before its route exists, so a demo session never reaches the real backend.
- **P8. Confirmations use a CloudK8s-local `ConfirmDialog`.** `components/ui/AlertDialog.tsx` autofocuses the confirm button and uses rose, amber, indigo and Font Awesome, which breaks §14 ("the destructive or restarting choice is never the default button") and the guard. `components/CloudK8s/shared/ConfirmDialog.tsx` uses the same RAC primitives (`ModalOverlay`, `Modal`, `Dialog`, `Heading`, `Button`), greyscale, with initial focus on Cancel. The shared `AlertDialog` is untouched.
- **P9. Null config means `404 K8S_CLUSTER_NOT_REGISTERED` for every method** (design-review NIT 4). The interceptor applies one rule after entitlement passes.
- **P10. Readiness properties are registered with `@EnableConfigurationProperties` on `K8sAutomationWebConfig`**, and `K8sCapabilitiesService` takes a `Clock` through a package-private test constructor (`Clock.systemUTC()` in the Spring constructor). The codebase has no `@ConfigurationProperties` or `Clock` bean yet, so this adds no global bean.
- **P11. Routing is a pure resolver plus a hook.** `resolveSectionRoute(registry, legacyMap, search)` is pure and unit-tested; `useEksSectionRoute` wraps it. Slice 5 reuses the resolver for GKE and AKS with their own registries.
- **P12. The tab-permission checkbox is one shared component**, `components/Shared/XamTabPermissionToggle.tsx`, rendered by both pickers, so the D2 rules are tested once.
- **P13. The published engine contract wins on wire details** (design-review NIT 1): container reason `LIMIT_MOVED` replaces `LIMIT_RAISED`, container `OOM_RISK` exists, and the disabled example is `clusterAccess: null`, `executionPath: "NONE"`.
- **P14. Visual verification runs a task-folder headless Chromium script**, following `/Users/apple/Desktop/XamOps-New/.agents/tasks/autospotting-release-safety-2026-10-05/ui-check/run-ui-check.cjs`: build with `--outDir RUN/fe-dist`, demo mode through `sessionStorage`, `playwright-core` from `/Users/apple/.npm/_npx/2c10347c988d3245/node_modules/playwright-core`. Nothing is added to the repo.
- **P15. GKE/AKS (optional) is limited to the page shells and the Automation explanation.** Their tab contents keep today's styling, are outside the guard, and are listed as a follow-up.
