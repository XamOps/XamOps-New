## 2026-06-18 - [CRITICAL] Fix exposed agent management endpoints
**Vulnerability:** The XamOps Agent API was protected by an overly permissive AntPathRequestMatcher("/api/v1/agent/**") permitAll() wildcard in SecurityConfig.java. This exposed management endpoints like /api/v1/agent/install-info (leaking the global API key) and /api/v1/agent/db/config (allowing unauthenticated modification of DB settings) to the public internet.
**Learning:** Wildcard permitAll() rules in SecurityConfig can inadvertently expose management or sensitive endpoints that share a common path prefix with public/agent-facing APIs. Internal API key validation in controllers is a good secondary defense (defense-in-depth), but should not be relied upon to protect management endpoints that were never intended to be public.
**Prevention:** Always use explicit, granular RequestMatchers for public APIs instead of broad wildcards. Management and configuration endpoints should default to requiring a valid user session.
