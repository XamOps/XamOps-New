## 2026-03-29 - Hardening Agent API Whitelist and Logging
**Vulnerability:** Overly permissive wildcard whitelist for `/api/v1/agent/**` allowed unauthenticated access to sensitive management endpoints like `/install-info` (which leaked the global API key) and DB agent registration/configuration. Additionally, the `CommonsRequestLoggingFilter` was configured to log all headers and payloads, potentially exposing session cookies, passwords, and API keys in system logs.
**Learning:** Broad wildcards in security configurations are a primary source of broken access control. Developers often use them for convenience during initial development but fail to narrow them down, leaving internal management APIs exposed to the public.
**Prevention:** Always use specific, full-path matchers (or at least narrower wildcards) for public/whitelisted endpoints. Disable sensitive logging (headers, payloads) in production environments by default; only enable them temporarily for debugging specific issues.
