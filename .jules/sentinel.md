## 2026-07-27 - [Hardening SOC2 Program Endpoints]
**Vulnerability:** The newly added `CompAiController` (handling `/api/soc2/**` endpoints) lacked method-level or class-level `@PreAuthorize` security annotations. If a developer accidentally misconfigured the central `SecurityConfig.java` to make `/api/soc2` public or broad permitAll wildcards matched it, the sensitive compliance operations (personnel details, vendor deletion, risks updates) would be exposed to unauthenticated public requests.
**Learning:** High-level central security filters in `SecurityConfig.java` can easily suffer from regressions or misconfigurations over time. Controllers should utilize defense-in-depth security annotations directly on the class or methods.
**Prevention:** Always add class-level `@PreAuthorize("isAuthenticated()")` (or more specific roles like `@PreAuthorize("hasAuthority('...')")`) on UI-facing and administrative Spring controllers. Write reflection-based security tests (`CompAiControllerSecurityTest.java`) to assert the presence of these annotations on the classes to prevent subsequent PRs from introducing security bypass regressions.
